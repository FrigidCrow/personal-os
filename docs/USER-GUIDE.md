# Personal OS 使用说明书

这份说明只讲怎么用，不讲复杂架构。

## 1. 打开系统

最简单的方法：双击桌面的 `启动 Personal OS.command`。

然后打开：

- Personal OS：`http://127.0.0.1:5273`
- OpenWorker：`http://127.0.0.1:5274`

如果页面打不开，先在项目目录运行：

```bash
npm run healthcheck
```

## 2. 左侧五个区域

### 今天

看今天需要处理的事，例如：

- 正在运行；
- 等你输入；
- 等你审批；
- 等你验收；
- 已失败，需要处理。

### 项目

一个项目可以绑定：

- 本地 Git 仓库；
- Obsidian 路径；
- 工作流、运行、成果和投入产出。

### 雷达

这里管理可以重复执行的工作流。机会雷达只是其中一个工作流。

### 运行

看每一次实际执行。这里能看到日志、结果、审批、成本和重试。

### 资产

看成果、Obsidian 知识和财务账本。

## 3. 第一次创建自动工作流

### 第一步：创建项目

进入“项目”，点击“新建项目”。

如果要用 Codex，必须填写一个真实存在的 Git 仓库路径。OpenWorker 和内置 Runtime 可以不填，但绑定项目后更容易整理成果。

### 第二步：准备 Skill

进入“雷达”，点击“Skill 工作台”。

填写：

- 机器名称：例如 `daily-ai-news`；
- 版本：第一次用 `1.0.0`；
- 显示名称：例如“每日 AI 新闻”；
- 用途说明：一句话说清它做什么；
- 执行方法：写清步骤、输入、输出、门槛和完成条件。

先点“检查 Skill”。检查通过后，再点“发布这个版本”。

发布会写入当前仓库的 `.agents/skills`。它不会让 Agent 自己修改 Skill。

### 第三步：新建雷达

点击“新建雷达”，然后选择：

- Runtime：Codex、OpenWorker、内置 Runtime 或本地命令；
- 固定 Skill；
- 所属项目；
- 执行要求；
- 超时时间；
- 最大尝试次数。

保存后，这一版不会被仓库里的后续修改悄悄改变。

### 第四步：运行体检

打开刚创建的雷达，点击“运行体检”。

体检会检查：

- 工作流是否启用；
- Runtime 是否可用；
- Codex 的 Git 仓库是否存在；
- Skill 快照是否完整；
- 有没有定时；
- 重试次数是否合理。

“提醒”可以继续运行；“失败”需要先处理。

### 第五步：设置定时

点击“添加定时”，填写：

- 名称；
- Cron 表达式；
- 时区；
- 是否允许错过后补跑一次。

例如每天早上 8 点：

```text
0 8 * * *
```

时区通常使用：

```text
Asia/Tokyo
```

## 4. 每天怎么执行

流程是：

`定时到点 → Personal OS 创建 Run → Runtime 执行 Skill → 回写进度和结果 → 你在运行页验收`

定时任务不会直接绕过 Personal OS。每次执行都有独立的 Run、日志和审计记录。

如果临时网络错误、Runtime 暂时不可用或执行超时，定时 Run 会自动创建下一次尝试。达到“最大尝试”后会停下，不会无限循环。

手动运行失败不会偷偷自动重试。你可以在“运行”页决定是否重试。

## 5. 怎么修改一个正在使用的工作流

不要直接覆盖旧版本。按下面做：

1. 在 Skill 工作台选择旧 Skill；
2. 修改执行方法，并把版本从 `1.0.0` 改成 `1.0.1`；
3. 检查并发布；
4. 打开旧雷达，点击“创建新版”；
5. 选择新 Skill，保存为新版本；
6. 回到定时规则，选择新版；
7. 点击“确认换绑”；
8. 再运行一次体检和手动测试。

旧工作流、旧 Run 和旧成果都会保留。定时规则只有在你点击“确认换绑”后才会切换。

## 6. 运行失败怎么办

先进入“运行”，打开失败的 Run，看这三处：

1. 错误信息；
2. 最后几条日志；
3. 是第几次尝试。

常见处理：

- Runtime 不可用：检查 Codex/OpenWorker 是否启动；
- Codex 找不到仓库：检查项目里的 Git 路径；
- 等待输入：填写问题答案；
- 等待审批：看清动作和风险后再决定；
- 没有结构化结果：让 Skill 明确调用 `submit_run_result`；
- 达到最大尝试：先修复原因，再手动重试。

不要为了让状态变绿而把失败标成成功。

## 7. 怎么把结果放进 Obsidian

进入“资产 → 知识”：

1. 添加 Vault；
2. 填写 Vault 的本地路径；
3. 点击重新索引；
4. 搜索已有笔记，或点击“新建笔记”。

系统只允许受控写入 `Inbox`、`Generated` 和 `Reports`。它不会随意覆盖你的旧笔记。

目前 Agent 可以搜索已索引的知识，但不能直接任意改写 Obsidian。需要沉淀的结果可以先登记为成果，再由你创建或确认笔记。

## 8. 怎么记录投入产出

进入“资产 → 财务”。

你可以记录：

- 账户；
- 收入和支出；
- 预算；
- 现金流预测；
- 某个项目或雷达分摊了多少钱；
- 预计收入、承诺成本和投入时间。

Agent 不能直接修改历史财务事实。它只能提出变更建议，最终由你审批。

## 9. 安全规则

- 不要把 API Key 写进 Skill、任务说明或 Obsidian；
- 不要把数据库、日志、密钥和下载音频提交到 Git；
- 付款、购买、联系客户、发布内容、删除文件和生产部署都要人工确认；
- Skill 发布和定时换绑都由你在 Web 中操作；
- 看到不明审批时，先拒绝，再检查 Skill 和运行日志。

## 10. 更新系统

在项目目录运行：

```bash
npm install
npm test
npm run typecheck
npm run lint
npm run build
npm run deploy:runtime
npm run launchagent:install -- --apply
npm run healthcheck
```

正式数据不会因为重新构建而清空。更新前仍建议执行：

```bash
npm run backup
```
