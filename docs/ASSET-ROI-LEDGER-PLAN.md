# 资产投入产出账本计划

**状态**：Implemented and verified
**日期**：2026-07-30
**所属模块**：资产 → 投入产出

## 1. 一句话发布说明

Personal OS 将为每个项目、Radar、产品、实验或自定义经营事项建立一份可追溯账本，让用户随时看清实际投入了多少钱、投入了多少时间、实际收回了多少钱、是否回本，以及每笔钱最终产生了哪些 Run 和资产。

## 2. 要解决的问题

现有“资产”可以回答“做出了什么”，但不能回答：

- 这个东西到现在实际花了多少钱？
- 哪些费用来自 API、订阅、投流、外包或平台抽成？
- 已经实际到账多少，预计收入又有多少？
- 是否回本，现金利润和 ROI 分别是多少？
- 哪次 Radar/Run 产生了成本，最终又形成了什么报告、代码或收入？

本模块不是通用财务软件。它是一份与 Personal OS 执行链直接关联的单人经营账本。

## 3. 核心口径

### 3.1 经营单元

“某一个东西”在数据模型中称为**经营单元**，在界面上使用更直观的名称“账本”。每本账可以直接绑定：

- 一个 Project；
- 一个 Radar Workflow；
- 一个收入资产或实验；
- 一个具体 Artifact；
- 一个用户自定义事项，例如“汽水热歌原创账号第一期”。

每笔账目只能属于一本主要账本，避免同一笔金额在多个项目中重复计入。它可以附加关联 Run、Workflow、Artifact 和凭证路径，用于追溯来源。

### 3.2 现金账与经营账分离

| 口径 | 包含内容 | 用途 |
|---|---|---|
| 现金账 | 已支付成本、已到账收入、退款 | 权威利润、回本和现金 ROI |
| 经营账 | 时间投入、待支付成本、预期/已开票收入、非现金投入 | 评估真实精力与未来可能性 |

预计收入不能计入实际产出；计划成本不能计入实际投入。所有汇总必须明确标注“实际”或“预计”。

### 3.3 权威计算

```text
实际投入 = 已支付费用 - 已收到的费用退款
实际产出 = 已到账收入 - 已退给客户的金额
净现金收益 = 实际产出 - 实际投入
现金 ROI = 净现金收益 / 实际投入
回本进度 = 实际产出 / 实际投入
```

当实际投入为 0 时，不显示无限 ROI，而显示“零现金投入，ROI 暂不可计算”。

时间投入以小时单独展示。只有用户主动设置机会成本时，系统才额外计算“经济成本”和“经济 ROI”，并且绝不替代现金账。

## 4. 账目模型

### 4.1 账目类型

| 类型 | 状态 | 计入实际汇总的条件 |
|---|---|---|
| 成本 | 计划、已承诺、已支付、已退款 | 只有已支付；退款冲减投入 |
| 收入 | 线索、预期、已开票、已到账、已退款 | 只有已到账；退款冲减产出 |
| 时间 | 已记录 | 只计小时，不自动折算现金 |
| 调整 | 增加、冲销 | 必须填写原因并保留修改轨迹 |

### 4.2 成本分类

- LLM/API 消耗；
- 软件订阅；
- 广告与渠道测试；
- 外包与服务采购；
- 平台手续费；
- 设备与素材；
- 差旅、物流及其他。

### 4.3 每笔记录的最小字段

- 经营单元；
- 类型、分类、状态；
- 原币金额、币种、发生日期；
- 人工录入或系统来源；
- 备注；
- 可选关联 Project、Radar、Run、Artifact；
- 可选凭证文件路径；
- 创建时间、修改时间和冲销关系。

外币保留原币金额与当时采用的手工汇率，并折算为用户设置的本位币。MVP 默认本位币为人民币；系统不静默使用实时汇率。

## 5. 自动归集与防止假账

- Runtime 只有返回可信的实际费用时，才可以自动生成“已支付”成本记录。
- 只有 token 数而没有价格时，显示“用量已知、金额未知”，不能按 0 元处理。
- 自动记录必须保留 Runtime、Run、计费来源和计算明细。
- 人工输入的预期收入永远保持“预计”，不能被一次 Run 自动改成“已到账”。
- 收入到账、退款和现金支出默认由用户确认；系统不连接支付或自动转账。
- 共享订阅通过“分摊”归属多个经营单元。分摊完成后，只统计子项，原始总账不再次计入，防止重复成本。
- 已被汇总引用的账目不直接删除，只允许冲销或新增更正记录。

## 6. 页面结构

入口位于一级导航“资产”内，资产页包含两个主视图：

1. **成果库**：报告、文档、Skill、代码、Obsidian、实验结论。
2. **投入产出**：经营单元、账目、回本和 ROI。

### 6.1 投入产出总览

- 时间范围：本月、今年、全部、自定义；
- 汇总卡：实际投入、实际产出、净现金收益、已回本单元；
- 账本列表：名称、绑定对象、实际投入、实际产出、净收益、回本进度、最近账目；
- 分开显示预计收入和待支付成本，不混入实际汇总；
- 支持按 Project、Radar、资产类型和状态筛选。

### 6.2 账本详情

```text
名称 / 绑定对象 / 状态
实际投入 | 实际产出 | 净现金收益 | 现金 ROI | 时间投入

趋势          账目流水          关联成果
成本与收入图  每笔费用/收入      Run、报告、代码、Obsidian、Skill
```

详情页必须能从任一账目反查对应 Run 或凭证，也能从任一成果看到它所属经营单元及累计投入产出。

### 6.3 快速记账

“记一笔”只要求先选择账本、成本/收入/时间、状态和金额/时长。高级字段折叠显示。Run 详情和 Radar 详情也提供带好上下文的“记为成本/登记收入”入口。

## 7. MVP 范围

### 本期实现

- 经营单元创建与绑定；
- 成本、收入、时间和冲销记录；
- 人民币本位币与手工外币换算；
- 实际/预计双口径；
- 净收益、现金 ROI、回本进度；
- Project/Radar/Run/Artifact 反向关联；
- 本地文件凭证链接；
- Runtime 已知实际费用的自动归集，未知费用明确标记；
- CSV 导出与本地备份。

### 本期不实现

- 银行卡、微信、支付宝或电商平台自动对账；
- 发票、税务申报和正式会计科目；
- 自动付款、自动退款或自动开票；
- 多人审批和企业报销；
- 自动抓取实时汇率；
- 把预期收入自动判定为到账。

## 8. 成功指标

| 目标 | 指标 | 目标值 |
|---|---|---:|
| 看清单项投入产出 | 打开经营单元到看到实际投入/产出 | 1 次点击 |
| 防止预计冒充实际 | 预计金额进入实际汇总的错误数 | 0 |
| 保持执行可追溯 | 自动成本拥有 Run 与来源明细 | 100% |
| 避免重复计算 | 同一原始金额被现金汇总重复计入 | 0 |
| 低摩擦记账 | 手工新增普通账目所需必填项 | 不超过 5 项 |

## 9. 实施顺序

1. 定义经营单元、账目、分摊与冲销领域模型。
2. 添加非破坏性 SQLite 表和索引，不修改现有收入资产历史。
3. 实现数据库聚合与 API，所有金额计算在 Domain/Database 完成。
4. 在“资产”中实现投入产出总览、经营单元详情和快速记账。
5. 给 Project、Radar、Run、Artifact 增加反向入口。
6. 接入 Runtime 可信费用，并对金额未知状态做显式呈现。
7. 完成迁移、计算精度、重复分摊、移动端和可访问性验证。

## 10. 关键验收

- 100 元已支付成本和 300 元已到账收入必须得到：投入 100、产出 300、净收益 200、ROI 200%。
- 300 元“预计收入”不得改变实际产出、净收益或 ROI。
- 10 小时时间投入默认只显示 10 小时，不折算现金。
- 一笔 100 元共享订阅分摊为 40/60 后，总投入仍为 100 元，不是 200 元。
- 收入退款和成本退款分别正确冲减产出和投入。
- 金额未知的 Runtime 用量不能显示为 0 元成本。
- 删除经营单元前必须处理其账目；已入账记录只能冲销，不能静默消失。
- 所有金额使用整数最小货币单位保存，避免浮点误差。
